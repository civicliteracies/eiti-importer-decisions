The deduplication pipeline

One organisation is written many different ways across EITI disclosures. This is how the importer resolves all of them to a single canonical entity — so a company's payments land on one page and every total is right.

What deduplication does

ZCCM INVESTMENTS HOLDINGS PLC Zambia Consolidated Copper Mines ZCCM-IH ZCCM Z.C.C.M. Investments Zambia Consolidated Copper ЗЦЦМ
One canonical entity Zambia Consolidated Copper Mines

The same organisation, disclosed seven different ways across countries and years, resolved to one identity with a stable id. Do that for every company, agency, and project, and the country totals finally add up.

The pipeline below is how that resolution happens — top to bottom. Every name is grouped with the ones that look like it, every match is reviewed before it changes anything, and the result is published as the entity list the importer reads. Drag to move around and scroll to zoom.

How to read it

  1. Follow it top to bottomNames come in at the top and leave as a published list at the bottom. Each step takes the result of the one above and hands its own result down.
  2. Three lanes that never crossCompanies, government agencies, and projects are resolved separately. A company and a government body that are the same organisation keep separate identities on purpose — one is a payer, the other a recipient, and merging them would blur the money flow.
  3. Every match is reviewedThe ringed review steps are the checkpoints. The first asks “did we group one entity as several, or several as one?”; the second, in Stage 2, asks “are these two actually the same?”
  4. Stage 2 is a set of filtersEach filter spots look-alikes a different way — similar names, an acronym ↔ full name match, bracketed variants, the same name across countries, shared rare words — and they all flow into the same review and merge. A parent company and its subsidiary are always kept apart.
  5. A new idea is a new filterThat shared review-and-merge is why a new way to spot look-alikes slots in beside the others — without rebuilding any of the earlier steps.
One convergence point — the published entity list — is what the importer reads at import time and the corpus tester guards against regression. For the engineering detail behind each step, see the pipeline concept map and operator runbook in the project documentation.
